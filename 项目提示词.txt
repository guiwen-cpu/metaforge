一、项目总纲提示词（先喂这段）
text
你是一位资深全栈架构师，精通低代码平台、Java 生态、Vue3 生态和工作流引擎。
我要开发一个「通用型低代码开发平台」，请你作为我的长期技术顾问，参与架构设计、模块拆分和代码生成。

【产品定位】
面向学校教务信息化系统、公司办公系统的通用低代码平台。
目标用户：学校老师、教务人员、公司 HR/行政/业务人员，以及少量专业开发者。
核心价值：可视化搭建 + 少量代码扩展，快速交付管理系统。

【前端技术栈】
- Vue3 + Vite + TypeScript
- TailwindCSS
- Axios
- Element Plus
- Pinia
- 图片/视频/办公文件上传：阿里云 OSS SDK 客户端直传（STS 临时凭证）

【后端技术栈】
- Java + Spring Boot
- Flowable（工作流引擎，BPMN）
- BFF 层（Spring Boot 实现，聚合元数据与业务数据）
- PostgreSQL（元数据 + 业务数据，善用 JSONB）
- Redis（缓存、会话、分布式锁）
- 阿里云 OSS（对象存储）

【核心模块】
1. 可视化页面设计器：拖拽布局、响应式配置
2. 数据模型设计器：定义实体、字段、关系（类似数据库建模）
3. 逻辑编排引擎：可视化定义业务逻辑、工作流、规则
4. 集成能力：连接 API、数据库、第三方服务
5. 一键发布：生成 Web、移动端、小程序等多端应用
6. 代码导出/扩展：支持在特定环节写自定义 TS 代码
7. 自定义组件：支持注册自定义 Vue 组件
8. 内置页面模板：增删改查页面（表格、分页、搜索、弹窗表单）
9. 表单类型：创建型表单，含图片/视频/办公文件上传
10. API 调用编排
11. 审批流页面：节点、条件分支、人员选择

【补充功能（必须全部包含）】
A. 多租户与权限体系：租户隔离、用户、角色、组织架构、数据权限
B. 元数据版本管理与回滚
C. 统一组件契约与 Schema 协议（核心地基）
D. 自定义组件沙箱隔离
E. 出码（代码导出）引擎
F. AI 辅助生成：自然语言生成表单/页面/流程
G. 模板市场/应用市场

【架构原则】
- 元数据驱动：控制平面 + 数据平面 + 运行时引擎共享同一份 Schema
- 前后端通过统一 Schema 协议通信
- 所有业务表带租户标识
- 元数据变更版本化、可回滚
- Schema 设计预留语义描述字段，为 AI 接入做准备

请先确认你理解了这个项目，然后我们按模块逐步深入。
二、分模块提示词（按需投喂）
模块 1：统一 Schema 协议设计
text
请为我的低代码平台设计「统一组件契约与 Schema 协议」，要求：

1. 一套 JSON Schema，能同时描述：
   - 页面布局（拖拽树结构、响应式断点）
   - 数据模型（实体、字段、关系、类型）
   - 表单（字段类型、校验、联动、上传配置）
   - 逻辑编排（节点、连线、条件、动作）
   - 审批流（BPMN 映射关系）
2. 支持版本号、租户 ID、语义描述字段（供 AI 使用）
3. 给出完整的 TypeScript 类型定义
4. 给出一个「请假审批表单 + 流程」的完整 Schema 示例
5. 说明前端渲染引擎如何消费这份 Schema，后端如何存储（PostgreSQL JSONB）
模块 2：数据模型设计器 + 动态建表
text
请设计「数据模型设计器」的后端方案：
1. 用户在可视化界面定义实体、字段、关系，如何映射到 PostgreSQL？
   - 方案 A：动态建物理表
   - 方案 B：JSONB 单表存储
   - 请对比并给出推荐方案及混合策略
2. 字段类型支持：文本、数字、日期、布尔、枚举、富文本、图片、视频、文件、关联实体
3. 实体关系：一对一、一对多、多对多如何建模
4. 元数据表结构设计（DDL）
5. 动态 CRUD API 的设计（Spring Boot 实现）
6. 如何保证多租户隔离
模块 3：Flowable 审批流集成
text

2. 人员选择如何映射到 Flowable 的候选人/候选组/表达式？
3. 条件分支如何用 Flowable 的排他网关/并行网关实现？
4. 审批页面（待办、已办、我发起的、流程详情）的 API 设计
5. Flowable 与多租户的结合方案
6. 审批表单数据如何与 Schema 体系打通
7. 给出 Spring Boot 集成 Flowable 的核心代码结构

text

4. 接口鉴权、租户识别、缓存策略
5. 给出 Spring Boot BFF 的模块划分和核心代码骨架

text
